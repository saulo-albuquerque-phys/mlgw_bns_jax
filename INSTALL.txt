================================================================================
  Setup Instructions — mlgw_bns_jax on IGWN / LIGO Jupyter Server
================================================================================


QUICK START (IGWN JupyterHub)
-----------------------------

   Open a terminal on the IGWN Jupyter server and run:

   git clone -b copilot/add-reduced-order-quadrature-model \
     https://github.com/saulo-albuquerque-phys/mlgw_bns_jax.git
   cd mlgw_bns_jax
   bash setup_igwn.sh

   Then select the "mlgw-bns-jax" kernel in any notebook.

   The script handles all known IGWN compatibility issues automatically:
   - Creates an isolated conda env with --override-channels (avoids base conflicts)
   - Pins JAX to 0.4.38 (NetKet and SHARPy try to upgrade to 0.9.x)
   - Pins setuptools < 71 (for pkg_resources compatibility)
   - Clones SHARPy and registers the Jupyter kernel


MANUAL SETUP (step by step)
----------------------------

1. CLONE THE REPOSITORIES

   git clone -b blackjax_ns_gw_pe \
     https://github.com/saulo-albuquerque-phys/mlgw_bns_jax.git
   cd mlgw_bns_jax
   git clone https://github.com/saulo-albuquerque-phys/sharpy.git _sharpy_repo


2. CREATE THE CONDA ENVIRONMENT

   Do NOT use `conda env create -f environment.yml` on IGWN — it will likely
   fail due to base environment conflicts.  Instead use:

   conda create -n mlgw-bns-jax -c conda-forge --override-channels -y \
     python=3.11 pip framel lalsuite gwpy ipykernel \
     numpy=2.0 scipy matplotlib h5py astropy numba \
     pandas scikit-learn tqdm
   conda activate mlgw-bns-jax


3. INSTALL PIP PACKAGES

   # JAX stack (MUST be pinned to 0.4.38)
   pip install "jax[cpu]==0.4.38" jaxopt optax equinox flax

   # Waveform & PE tools
   pip install ripplegw corner anesthetic seaborn \
     PyYAML toml dacite joblib sortedcontainers requests

   # NetKet — will try to upgrade JAX, re-pin after
   pip install "NetKet==3.20.5"

   # Git-only packages
   pip install \
     "blackjax @ git+https://github.com/gabrieledemasi/blackjax@main"

   # CRITICAL: re-pin JAX (NetKet upgrades it to 0.9.x)
   pip install "jax[cpu]==0.4.38"

   # Ensure pkg_resources works
   pip install "setuptools<71"


4. INSTALL LOCAL PACKAGES (use --no-deps to avoid JAX upgrade)

   pip install --no-deps -e ./_sharpy_repo
   pip install --no-deps -e .

   # Re-pin JAX one more time (SHARPy may have upgraded it)
   pip install "jax[cpu]==0.4.38"


5. REGISTER THE JUPYTER KERNEL

   python -m ipykernel install --user \
     --name mlgw-bns-jax --display-name "mlgw-bns-jax"


6. USE IN JUPYTER

   Open any notebook and select the kernel "mlgw-bns-jax".

   Key notebooks:
     - build_roq_basis_numpy.ipynb             → Build ROQ basis (NumPy, no JAX)
     - build_roq_basis_jax_colab.ipynb         → Build ROQ basis (JAX, GPU, Colab)
     - roq_pe_mlgw_bns_jax.ipynb               → ROQ-accelerated parameter estimation
     - sharpy_mlgw_bns_jax_pe_fixedsky.ipynb   → Standard (non-ROQ) PE with SHARPy


KNOWN ISSUES & SOLUTIONS
-------------------------

1. `conda env create -f environment.yml` fails
   → Use `conda create ... --override-channels` instead (step 2 above).
   → The IGWN base environment has pinned packages that conflict with the
     environment.yml spec.

2. JAX version keeps getting upgraded to 0.9.x
   → NetKet and SHARPy declare loose JAX deps that pull in 0.9.x.
   → Always re-run `pip install "jax[cpu]==0.4.38"` after installing them.
   → Use `--no-deps` for editable installs of sharpy and mlgw_bns.

3. `ModuleNotFoundError: No module named 'pkg_resources'`
   → setuptools ≥ 72 no longer bundles pkg_resources.
   → Fix: pip install "setuptools<71"

4. JAX OOM during ROQ basis construction
   → Use roq_builder_jax.py, which manages memory with streaming batches
     and vmap to avoid OOM.  It supports checkpoint/resume so interrupted
     builds can continue from where they left off.

5. `framel` not found / cannot read .gwf files
   → framel is only available via conda-forge, not pip.
   → Already included in the conda create command above.


================================================================================
  BUILDING THE ROQ BASIS
================================================================================

There are now two independent paths for constructing the ROQ basis:

  A) JAX-native route (recommended) — uses roq_builder_jax.py, a standalone
     JAX reimplementation of the ROQ algorithm with JIT-compiled waveform
     kernels, jax.vmap batching, streaming memory management, and
     checkpoint/resume support.  Can run on GPU for faster builds.

  B) NumPy route (legacy) — uses the original mlgw_bns model with the
     JenpyROQ library.  No JAX required at build time.  This route is
     kept for reference but is no longer actively maintained.  If you
     need to use it, install JenpyROQ separately:
       pip install "JenpyROQ @ git+https://github.com/GCArullo/JenpyROQ.git"


JAX-native ROQ Builder (recommended)
--------------------------------------

   The JAX-native builder (roq_builder_jax.py) re-implements the full ROQ
   construction algorithm using JAX.  It is designed for environments with
   GPU access (Google Colab with GPU, HPC clusters) but also works on CPU.

   Key features:
     - JIT-compiled waveform kernels (compiled once, reused for all batches)
     - jax.vmap for parallel batched waveform generation
     - Streaming memory management — training sets are never fully materialised
       in RAM; waveforms are generated in small batches (default vmap size = 8)
     - Checkpoint/resume — each phase (preselection, enrichment, EIM) is
       checkpointed to disk.  If interrupted, re-running with resume mode
       skips already-completed phases automatically
     - Built-in validation — runs mismatch tests after each basis build
     - Saves build metadata (basis sizes, timings) to build_metadata.json

   From a terminal (CPU):
     conda activate mlgw-bns-jax
     cd ~/mlgw_bns_jax
     python roq_builder_jax.py                                  # default config
     python roq_builder_jax.py config_roq_mlgw_bns_jax_gw170817.ini  # custom

   CLI flags:
     --no-resume   Force a fresh build (ignore existing checkpoints)

   From Google Colab (GPU-accelerated):
     Open build_roq_basis_jax_colab.ipynb, select a GPU runtime, Run All.
     The notebook auto-installs jax[cuda12] and clones the repo.

   For GPU usage, install JAX with CUDA support instead of CPU:
     pip install "jax[cuda12]"

   Output:  roq_basis_mlgw_bns_jax/ROQ_data/ (linear + quadratic interpolants)

   The builder reads configuration from a .ini file or uses sensible
   defaults (23–2000 Hz, 128 s segment, tolerance 1e-4/1e-6).


VALIDATING AND PACKAGING THE ROQ BASIS
----------------------------------------

   After building, run the validation/packaging script:

     python validate_and_package_roq.py

   This will:
     1. Check that all expected output files exist
     2. Run mismatch validation with 200 random waveforms
     3. Package the small files needed for PE into roq_pe_package.zip

   Upload roq_pe_package.zip to Google Drive for Colab-based PE.
